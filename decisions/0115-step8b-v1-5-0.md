## 1. The rulings, at the point of use

**E8 — arm files do not carry `channel_classes`.** `TOP_LEVEL_PUBLISHER` gains **`channel_classes`
and `discovery_channel_overlap`, both published by `step13b`**. The blocks become *real payload OR
block-absence*; an arm file states the absence, the merged document fills it, and **check S36 now
fails both directions** — a filled copy in an arm file, and an absence in the file that publishes it.
***`discovery_channel_overlap` was checked rather than assumed, as the ruling asked: it is the same
shape*** — Step 8's counts, no publisher, nothing stopping seven writers — **differing only in being
OPTIONAL, so the defect there was reachable rather than shipped.**

***One consequence, recorded as a spec choice rather than taken silently: Step 8's artifact is now
declared as a NINTH MERGE SOURCE***, `source_kind: non_arm_file`, filling those two blocks, which
name it in `merged_from`. **The ground is `0111` E6's own** — a block cannot arrive in the
reader-facing document with no recorded provenance — **and that argument does not distinguish a bias
ledger from a D9 bound.** If the count of eight is meant to be exact, the row comes out of two tables
and the two blocks lose their stamp; the effect is that the merge would then carry Step 8's figures
with no recorded source.

**E13 — publisher rows key on ARM IDENTITY.** S22 read `BLOCK_PUBLISHER` alone, which names a STEP,
and so required `waterfall`, `liveness_exclusions` and `retained_by_air_period` **wherever a `step9`
entry is primary — including a premiere-anchored arm, where the schema's own text says no producer
exists.** The validator now holds `NO_PRODUCER_AT_CLOCK_ORIGIN` **externally**, and at such an arm
**the FIGURE stops being required while the RECORD does not**: a stated absence passes, **silence
still fails.** Both halves are asserted in the selftest — the legal absence as a **required
non-failure**, the silence as a **mutation that must fail.**

**E14 — the adopted-rule revision joins the key.** The key is
**`(W_days, clock_origin, producing_step, adopted_rule_revision)`**, `$.arm_key.fields` states it,
S2 asserts uniqueness on it, **the `arm_id` label carries it** (`W108_s2_finale__step9__r6`), and
every arm, variant and cut entry names it.

***Where the revision is READ FROM, which the launch instruction asked to be decided:***
**`processed/step5/adopted_rule.json` — the eighth propagation surface, and the file where this
dimension was already occupied.** It carries **no first-class revision field**: the revision appears
only in KEY NAMES, so the reader scans every key for `approved_(?:rule_)?revision_(\d+)`, takes the
highest, and records **the key it came from and the file's SHA-12** in `$.adopted_rule_revision`.
**It read 6, from `_SUPERSEDED_FIGURES_CORRECTED_2026_08_13.approved_rule_revision_6`.**
**No match is a HARD STOP, not a default** — a default would be a typed revision wearing a reader's
clothes. **The adopted-rule file was NOT edited to add a field**: it is Step 5's output, and a
deliverable is corrected by rerunning the arm that produced it. **The inference is published as a
known limit and is §4's first residual.**

**E9/E15's fix is an EXTERNAL ANCHOR, derived from `STEP_DUALITY` as the finding said it could be:**
a dual step contributes arms `a` and `b`, a single-arm step contributes `sole`, plus the named
non-arm sources. **Every leg before it read the declared list against the file's own payloads, so a
subset closed against itself.** **And leg (e) now separates CONTRIBUTION from MENTION**: a
`declared_intervals` entry references a file, it is not a payload from one.

**E11's fix is `INTERVAL_CLASS_PUBLISHERS` plus an arm-identity clause** — an interval names a step
the spec lets publish that quantity class, and in an arm file names that file's own step and arm.
**The placeholders' two interval branches survive the fix**: a step that may publish a window-W
interval declares the agreeing and disagreeing pair on it; **a step that may not declares the same
pair on its own outcome-shares quantity, where the disagreement runs the other way** (binding cluster
account, resampled by show). `binding_cluster` was hard-coded `show` and is now a parameter.

**E12's fix is a closure between the schema and the table**, with the identity fields and `headline`
**exempted by name in the validator, outside the file under test.**

## 3. The ratification

**A synthetic STEP 13 ARM FILE — dual step, one arm — is built inside the selftest from the same
generator the deliverables come from**, validated, and asserted to carry **all six** of `0111` E1's
blocks in their **one-arm form**: one container each, `arms_in_this_file: one_arm`, arm key `a`,
producing step `step13`. **It is not written to `artifacts/`, so the deliverable count stays at
three.**

***It found a real defect on its first run.*** **S21's required branch families were keyed on ROLE
alone**, so a dual arm file was required to exercise **the premiere-anchored origin** and **two
absence statuses that are STEP 9's alone** — Step 9 reports Netflix's window on a different origin,
and **Step 13's grid is finale-anchored at every one of its eight arms.** **A Step 13 arm file
therefore failed S21 for holding exactly what the spec asks of it.** The branch families are now
restricted **by producing step as well as by role, with the restriction named in the file** as the
role restriction already was.

**And a second gap, in the selftest itself:** its headline read *"N of N checks shown to have
force"*, where **N was the count of what it happened to try**, not of what exists. **A check added to
the validator and to no mutation table was silently unexercised.** It now compares the two sets and
**fails on any check defined and never exercised** — `checks_defined_but_never_exercised`. **83
mutations, all with force, none undefined.**

## 4. Residuals, and one defect I do not own

1. **The revision is read by PARSING KEY NAMES**, because `adopted_rule.json` has no revision field.
   A newer revision written under a key name that does not match the pattern would leave the older
   one looking current. **Published as a known limit.** A first-class field in that file would remove
   the inference — **it is Step 5's output, so it is reported rather than edited.**
2. **The expected merge-source set is derived from a table that is itself a copy of the spec.** It
   catches a merge declaring fewer sources than the table knows about; it cannot catch a source the
   table has never heard of. **`S31` asserts the same table against each file's own `$.step_duality`,
   so a file written under a newer spec disagrees loudly rather than passing quietly.**
3. ***THE THREE-FIELD ARM KEY IS LIVE BESIDE THE FOUR-FIELD ONE***, unmarked, at
   **`task-sheet.md:820` and `:879`**, **`.claude/agents/analytics-engineer{,-b}.md:525`**, and
   **`.claude/agent-memory/second-brain/glossary-terms-and-thresholds.md:538`**. In `task-sheet.md`
   and both agent files **the superseded text sits BELOW its replacement in the same section** —
   the shape `0067`, `0076`, `0083` §3a, `0089` §3, `0091` and `0099` each fixed elsewhere.
   **`check_surfaces.py` cannot see it: the arm key is a STRUCTURAL CLAIM, not a number and not a
   registered withdrawn phrase** — `CLAUDE.md`'s third blindness class, and `0113` §2 recorded it
   for this exact string one entry ago. **Reported and not edited: propagating a ruling into the
   spec an arm reads is not an arm's to do.**
